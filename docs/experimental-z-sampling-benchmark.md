# Эксперимент: влияние привязки RTSTRUCT-контуров к RTDOSE Z

Статус: **только численное сравнение на синтетических 3D-фантомах**.
Ни один из новых методов не включён в клинический DVH, Dcc/Vcc или
TCP/NTCP. Результаты не подменяют сравнение с Monaco и не означают,
что исходный метод ближайшего среза корректен для всех ROI.

Задача: https://github.com/mesava/BioRT/issues/29

## Причина

DICOM RTSTRUCT задаёт контуры как координаты (x,y,z) в системе
координат пациента, но **не задаёт единственный обязательный способ**
восстановления трёхмерного ROI между контурными плоскостями.
Способ интерполяции, Z-охват конечных слоёв и дискретизация влияют
на DVH и объём, особенно для малых OAR.

Публикация Grammatikou et al., *J Appl Clin Med Phys* (2025),
DOI: 10.1002/acm2.70235, посвящена именно валидации Monaco
в SRS, включая аналитические DICOM-объекты и влияние толщины
среза/разрешения дозовой сетки:
https://aapm.onlinelibrary.wiley.com/doi/full/10.1002/acm2.70235

Подробная DICOM-спецификация контуров:
https://dicom.nema.org/medical/dicom/current/output/chtml/part03/sect_c.8.8.6.html

## Сравниваемые численные правила

`ExperimentalContourZSampling.Compare(...)` вычисляет **три результата
для одного и того же RTDOSE и ROI**:

1. **LegacyNearestDoseFrame:** реальный текущий `MaskBuilder`.
   Каждый RTSTRUCT контур сразу переносится на ближайший дозовый кадр.
   Между контурными плоскостями никакое заполнение не производится.
2. **NearestContourPlane:** каждый центр RTDOSE-среза в объявленном
   Z-диапазоне получает маску ближайшего **RTSTRUCT контурного слоя**.
   На границе между двумя слоями при равном расстоянии выбирается нижний
   слой. Операции union/XOR выполняются внутри слоя.
3. **LinearBinaryOccupancy:** для каждого XY-центра вокселя бинарная
   принадлежность нижнему и верхнему контурным слоям смешивается
   с коэффициентом `t=(z-z0)/(z1-z0)`:
   `w(z)=(1-t)*I0+t*I1`. Частичная занятость допускается **только**
   внутри эксперимента. Это **не** линейная геометрическая
   интерполяция вершин/поверхности, **не** клинический DVH.

Возвращаются суммарная занятость в эффективных вокселях,
объём (см³), средняя доза и прямой `V(доза ≥ порога)` (%).
Для ясности последнее оценивается напрямую на исходных значениях
дозовых вокселей, **не** по округлённым 0,1 Gy бинам клинического DVH.

## Важное: концовки ROI (end caps)

Для двух экспериментальных методов доступны явно задаваемые правила:

- `NoExtrapolation`: считаются только центры дозовых слоёв между
  первым и последним контурными Z.
- `ExtendHalfDoseFrame`: крайние контуры продолжаются на половину
  шага RTDOSE за каждый край. Это **сценарное допущение**, не
  выводимое автоматически из RTSTRUCT.

LegacyNearestDoseFrame от этого выбора не зависит.

## Проверочные синтетические объекты

Все тесты используют координаты центров вокселей и известный
ручной расчёт.

| Сценарий | Legacy, см³ | Nearest contour, см³ | Linear occupancy, см³ |
|---|---:|---:|---:|
| Постоянное сечение 5×5 мм, контуры Z=0 и 4 мм; 5 кадров с шагом 1 мм | 0,050 | 0,125 | 0,125 |
| Сужение 4→1 воксель между Z=0 и 4 мм | 0,005 | 0,014 | 0,0125 |
| Один воксель XY, контуры Z=0,4 и 3,6 мм; без endcaps | 0,002 | 0,003 | 0,003 |
| Те же контуры, с half-frame endcaps | 0,002 | 0,005 | 0,005 |
| XOR-кольцо 3×3 с отверстием 1×1, два контурных слоя | 0,016 | 0,040 | 0,040 |

Важно: в примере постоянного сечения эталон `0,125 см³`
соответствует **заранее объявленному** физическому Z-слою от
-0,5 до +4,5 мм (толщина 5 мм), а не автоматически исходному
RTSTRUCT. Если интерпретировать 0 и 4 мм как строгие геометрические
границы без выходящих за них частей, объём будет другим.

Для постоянного сечения и квадратичного профиля дозы
`D(z)=z²` Gy на кадрах Z=0..4 мм:

- Legacy: Dmean = 8 Gy, V10Gy = 50%;
- два новых численных правила: Dmean = 6 Gy, V10Gy = 20%.

Это показывает, почему Z-метод может влиять и на дозиметрические
показатели даже при одинаковых исходных RTDOSE и RTSTRUCT.

## Границы применения

- Эксперимент запускается только явным вызовом научного API;
  `PlanAnalysisService` и UI по умолчанию его не используют.
- Не поддерживает неравномерные RTDOSE кадры, неосевые контуры,
  единственную RTSTRUCT плоскость и массивы более 5 млн дозовых
  вокселей.
- В рамках эксперимента нет реальной 3D поверхности, регистрации,
  интерполяции дозы, сглаживания или гарантии сохранения формы.
- Метод дробной бинарной занятости может создавать «призрачные»
  пространственные объёмы при больших сдвигах контуров, поэтому
  он **не** может быть объявлен клиническим алгоритмом на основании
  совпадения интегрального объёма.
- Не используйте численные различия из таблицы как допустимые
  погрешности для Monaco или клинических Dcc/Vcc.
- Имеющийся realistic Web fingerprint
  `d15422b0697ba418e944af9496e209a2d460b7972766d1482b6ecbe250c11dac`
  относится к производственному MaskBuilder и не изменяется
  этой экспериментальной проверкой.

## Следующая проверка перед каким-либо переключением

1. Подготовить независимые DICOM-аналитические фигуры (сферы
   диаметром 3–20 мм, цилиндры, конусы, раздельные острова, XOR).
2. Сопоставить по каждой структуре геометрический объём,
   Dmean, D2/D98, Vcc и градиентные дозы с аналитическим
   ground truth и с Monaco 6.1.4.
3. Задокументировать соглашения о конце контуров, пересечении
   отдельных островов, Z-зазорах и минимальном размере ROI.
4. Сохранить текущий клинический метод без изменения до завершения
   количественного commissioning.
