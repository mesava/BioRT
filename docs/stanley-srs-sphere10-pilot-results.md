# Stanley et al. 2021 — первый импорт и независимый обзор DICOM (20.11.2026)

**Статус:** архив получен, проверен и исследован. Эти результаты получены
внешним Python/numpy-декодером, **не** являются результатами BioRT
runtime или независимым отчётом Monaco 6.1.4. Клинические выводы
не делаются.

Публикация: Stanley et al., *Accuracy of dose-volume metric
calculation for small-volume radiosurgery targets*, Medical Physics,
2021, DOI: https://doi.org/10.1002/mp.14645.

Оригинал приложения: `mp14645-sup-0001-Supinfo.zip`.

Все 23656499 сохранённых 32-битных значений превышают UInt16.MaxValue.
Ранее `RtDoseReader` всегда читал их как UInt16 с шагом 2 байта.
Это критический источник неверной дозы. Исправлен в PR #52
(с тестами UINT16/UINT32 и проверкой формата пикселей).
Не используй результаты с 32-битным RTDOSE, рассчитанные
старой версией BioRT.

Заголовки **всех 12 RTDOSE** дополнительно проверены: каждый использует Transfer Syntax Implicit VR Little Endian, unsigned BitsAllocated=32 и DoseGridScaling=2E-05. При шаге CT 0,5 мм в RTDOSE 501 кадр, при шаге CT 1 мм — 251 кадр.

RTSTRUCT:

- **2043** контура, тип CLOSED_PLANAR;
- FrameOfReferenceUID согласован между RTPLAN, RTDOSE,

### Независимый Python/numpy pilot: все 50 GTV размером 10 мм

Метод: чтение raw UINT32 RTDOSE и масштабирование; для каждой
RTSTRUCT плоскости — **неинтерполированная** привязка к ближайшему
центру дозового кадра; внутри осевого XY — ray casting по
координатам центров вокселей (аналог текущего MaskBuilder).
Отчёт рассчитан по полному набору 50 GTV.

Аналитический объём сфер диаметром 10 мм:
`π×10³/(6×1000)=0,5235987756` см³.

| Показатель | Среднее по 50 | Минимум | Максимум |
|---|---:|---:|---:|
| Объём GTV (на дозовой сетке), см³ | 0,52448 | 0,512 | 0,532 |
| Отличие объёма от аналитического, % | +0,1683 | −2,2152 | +1,6045 |
| V20Gy внутри GTVxx_SHELL, см³ | 0,52450 | 0,512 | 0,532 |
| V10Gy внутри GTVxx_SHELL, см³ | 2,86322 | 2,848 | 2,884 |
| Paddick GI = V10Gy/V20Gy | 5,45937 | 5,38346 | 5,60352 |

Для GTV01:
- V(GTV01) = **0,527 см³**;
- объёмное отличие от аналитического = **+0,6496%**;
- средняя доза GTV01 = **23,2835 Gy**;
- V20Gy внутри GTV01_SHELL = **0,527 см³**;
- V10Gy внутри GTV01_SHELL = **2,870 см³**;
- GI = **5,44592**.

Эти числа относятся к **независимому Python-расчёту** и
только к выбранному набору с шагом Z=1 мм.
Они не подтверждают, что BioRT/.NET их воспроизводит.
Приведённые V10Gy и GI ещё не проверены по точной
аналитической модели дозы из первоисточника; это
дискретные показатели загруженного RTDOSE.

### Научно значимое уточнение

В Stanley величины V100% (V20Gy) и V50% (V10Gy) измеряются
**на специальных evaluation ROI `GTVxx_SHELL`**, а не
ограничиваются объёмом GTV. Подмена оценки shell на GTV
привела бы к очевидно ложному `V10Gy≈V20Gy`
и неправдоподобному gradient index.

Исследование также содержит аналитическую эталонную формулу
дозового распределения (Equation 1); для полноценной приёмки
нужно реализовать **её точное выражение** и сравнить
V20/V10/CI/GI с независимым эталоном.

## Следующая проверка

- Получить в BioRT C# результаты GTV01...GTV50
  специализированным локальным benchmark runner;
  НЕ запускать обычные TCP/NTCP для 101 исследовательской ROI.
- Сверить по каждой ROI объём, V20 и V10 против
  независимого Python отчёта с заранее заданными
  **численными** допусками (не клиническими).
- Проверить Memory/CPU для WebAssembly: RTDOSE ≈95MB
  raw, double[,,] ≈189MB; в полном Web импорте
  возможны дополнительное буферизование и расход памяти.
- В дальнейшем проверить 0,5-мм наборы и остальные диаметры,
  особенно сферы 3 и 5 мм, где дискретизация критична.
- Затем импортировать те же файлы в Monaco 6.1.4 и
  сравнить определённые *до расчёта* метрики.

Ни один бинарный DICOM из публикации не коммитится в GitHub.
