# Протокол внешней проверки BioRT: Stanley et al. SRS ground truth DICOM

Статус: **протокол подготовлен, исходные сторонние DICOM ещё НЕ загружены
и независимое сравнение BioRT ↔ Monaco НЕ проведено**.

Данный план продолжает Issue #29 после синтетических тестов
`ExperimentalContourZSampling` и
`AnalyticalSphereZBenchmarkTests`.

## 1. Первоисточники

**Stanley DN, Covington EL, Liu H, et al.**
*Accuracy of dose-volume metric calculation for small-volume
radiosurgery targets.*
Medical Physics, 2021, 48:1461–1468.
DOI: https://doi.org/10.1002/mp.14645

Официальная страница:
https://aapm.onlinelibrary.wiley.com/doi/10.1002/mp.14645

В разделе **Supporting Information** указан
`mp14645-sup-0001-Supinfo.zip` (около 269,9 MB), описание:
«A ground truth set of DICOM dose and structure set files that can
be imported and evaluated».

Ссылка издателя:
https://aapm.onlinelibrary.wiley.com/action/downloadSupplement?doi=10.1002%2Fmp.14645&file=mp14645-sup-0001-Supinfo.zip

Автоматический доступ к архиву со стороны издателя может
возвращать HTTP 403. **Не указывать, что файлы скачаны или
проверены, пока они не получены и не прошли checksum/manifest.**

**Grammatikou D, et al.** *Validation of dose-volume calculation
accuracy for intracranial stereotactic radiosurgery with
volumetric-modulated arc therapy using analytical and clinical
treatment plans.* J Appl Clin Med Phys, 2025.
DOI: https://doi.org/10.1002/acm2.70235

Работа применяет Stanley DICOM для проверки Monaco **6.1.2.0**.
В нашей клинике используется **Monaco 6.1.4**, поэтому
межверсионную эквивалентность предполагать нельзя.

## 2. Что в исходном исследовании

По методике Stanley:

- аналитические сферы диаметром **3, 5, 7, 10, 15, 20 мм**;
- 50 случайно расположенных сфер каждого диаметра;
- два набора синтетических КТ: пиксель 0,6×0,6 мм,
  толщина среза 0,5 и 1 мм;
- всего **600** целевых сфер;
- RTDOSE с дозовыми распределениями, построенными из
  аналитической модели для SRS;
- основные показатели: объём сферы, V100% (V20Gy),
  V50% (V10Gy), RTOG CI, Paddick GI.

Точные контрольные значения из аналитической дозовой формулы
Stanley должны быть извлечены из первоисточника/приложения
до утверждения V20Gy и V10Gy; нельзя восстанавливать их
по результату BioRT или по приблизительному описанию.

**Аналитические объёмы сфер**, не зависящие от TPS:

| Диаметр, мм | V = π D³ / 6, см³ |
|---:|---:|
| 3 | 0,014137 |
| 5 | 0,065450 |
| 7 | 0,179594 |
| 10 | 0,523599 |
| 15 | 1,767146 |
| 20 | 4,188790 |

Это математическая геометрия, не гарантированный
дискретный объём какой-либо RTDOSE или КТ сетки.

## 3. Приёмка и контроль архива

1. Скачать официальный ZIP и вычислить SHA-256 **локально**.
2. Сохранить манифест: DOI, URL, дата получения, размер,
   SHA-256, сведения о лицензии, список наборов.
3. Просмотреть ZIP без распаковки исполняемых файлов.
4. Отдельно проверить для каждого набора:
   RTPLAN, RTDOSE, RTSTRUCT, CT series (если есть),
   TransferSyntaxUID, FrameOfReferenceUID, число структур,
   размер/шаг RTDOSE, DoseGridScaling, ImageOrientationPatient,
   GridFrameOffsetVector, типы контуров.
5. Отметить отсутствие/несоответствие любой из обязательных
   геометрических связей; не отключать безопасность BioRT
   ради прохождения внешнего benchmark.
6. Не коммитить 269,9 MB архив в `main` и не встраивать
   его в GitHub Pages. Использовать локальное хранение
   или управляемый исследовательский набор.

Текущий `DicomBundleImporter` требует **один согласованный
RTPLAN + RTDOSE + RTSTRUCT**. Издательский архив целиком
может содержать много исследований и превысить лимиты
веб-загрузчика (число файлов, распакованный размер);
его нельзя загружать одним архивом без предварительного
разделения на согласованные наборы.

## 4. Независимый расчёт BioRT

Для каждого диаметра, CT-сеточного шага и каждой сферы:

- `Vgeometry = πD³/6` (аналитический эталон);
- `Vcontour-integral` для однозначных контуров,
  без необоснованного продолжения концов;
- `Vdose-grid` от настоящего `MaskBuilder`;
- экспериментальные
  `LegacyNearestDoseFrame`,
  `NearestContourPlane`,
  `LinearBinaryOccupancy`,
  с явно указанными вариантами Z end caps;
- V20Gy и V10Gy на соответствующих
  evaluation volumes (как в первоисточнике);
- CI и GI, только при точно подтверждённом
  определении индексов и reference isodoses;
- Dmean/Dmax и диагностические Dcc/Vcc по согласованному
  абсолютному объёму;
- число выбранных вокселей, фактический размер вокселя,
  Z-коллизии/охват и число малых ROI.

Важное ограничение: `PlanAnalysisService` сейчас
ориентирован на клинические критерии/структуры.
Для 600 benchmark-сфер целесообразен **отдельный
BenchmarkRunner**, использующий библиотеки чтения
DICOM и DVH, но не выбирающий TCP/NTCP и
не назначающий клинические критерии автоматически.

## 5. Матрица независимой валидации

| Источник | Объём структуры | V20Gy | V10Gy | Dcc/Vcc |
|---|---|---|---|---|
| Аналитическая геометрия/доза Stanley | точная модель | точная модель (после извлечения формулы) | точная модель (после извлечения формулы) | отдельный референс |
| BioRT — current MaskBuilder | дискретный | дискретный | дискретный | дискретный |
| BioRT — экспериментальные Z-методы | исследование | исследование | исследование | исследование |
| Monaco 6.1.4 | независимо экспортированный результат | TPS | TPS | TPS |

Для каждого показателя отдельно фиксировать:
абсолютное расхождение, относительное расхождение,
разрешение сетки, модель/метод заполнения контуров,
соглашение о крайних Z-слоях, сортировку и определение
объёмного порога, округления.

**Не вводить клинические допуски постфактум** после
получения результата. Сначала выбрать протокол и
набор критериев приемлемости с медицинскими физиками.

## 6. Дальнейший программный шаг

После получения дополнительных файлов:
1. выбрать один малый набор (например, диаметр 10 мм,
   CT slice 1 мм) и получить воспроизводимый local manifest;
2. реализовать парсер/отчёт benchmark по каждой из 50 сфер;
3. вычислить абсолютные эталонные значения из
   опубликовавшейся аналитической модели, без смешивания
   размеров и измерений;
4. сравнить BioRT с точной геометрией и Monaco 6.1.4;
5. только после этого рассматривать замену
   метода Z-проекции в основном `MaskBuilder`.

Оба контроля пользовательского synthetic patient
`15194691.zip` остаются отдельным commissioning case 001.
Изменения экспериментальных API их не должны менять.
